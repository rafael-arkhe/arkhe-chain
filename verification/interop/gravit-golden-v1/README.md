# Gravit interoperability golden vectors v1

Frozen 2026-10-28. Eight small primitive cases, selected without changing bytes
from the [2026-10-26 exchange](../gravit-2026-10-26/README.md).
`arkhe-vectors.json` uses the existing exchange job array; `expected.json` uses
the existing `{id, accepted, reason}` format. Expected verdicts are static inputs,
never generated by the verification command. `true` means accept this primitive
check, not acceptance of a complete Gravit decision or an Arkhe Verified Fact.

| Case ID | Expected | Check |
| --- | --- | --- |
| merkle-valid-0 | accept | Leaf 0 in a three-leaf RFC 6962 tree |
| merkle-wrong-leaf | reject | Same proof and root, leaf replaced with byte 00 |
| signature-valid | accept | Ed25519 signature on the exact witness message |
| signature-tampered | reject | Same key and signature, message replaced with byte 00 |
| quorum-valid | accept | Two distinct keys and configured operators, threshold 2 |
| quorum-insufficient | reject | Only one signature, threshold 2 |
| quorum-dependent | reject | Two keys assigned to the same operator |
| quorum-key-alias | reject | One key signing under two witness IDs |

## Byte and policy specification

Hex fields are lowercase raw bytes, with two characters per byte. Decode hex
before hashing or verifying. No JSON serialization is signed. IDs only label
cases. Integers are unsigned u64; reject malformed fields and unsupported kinds.
Roots, path hashes and public keys are 32 bytes; Ed25519 signatures are 64 bytes.

For inclusion, SHA-256 leaf hash is `H(00 || leaf)` and internal hash is
`H(01 || left || right)`, where 00 and 01 are single bytes. Split a tree at the
largest power of two strictly smaller than its size. Leaves, in order, are UTF-8
`arkhe-interop-a`, `arkhe-interop-b`, `arkhe-interop-c`, without terminators.
The root is `5128b63cc0fbd21844460760d5764ade0badf77535eee278c685a8807550f40d`.
`index` is zero-based; `size` counts leaves; `path` lists siblings bottom-up.
Require positive size, index below size, exact path consumption and root equality.
For the positive case, compute `H(01 || H(01 || H(00 || leaf) || path[0]) || path[1])`.
Arkhe calls `gguf::supply_chain::verify_inclusion` in `arkhe-verify-core`.

For signatures, use ordinary Ed25519 (no prehash, no context) over exactly
`message_hex`, with `key_hex` and `signature_hex`. Arkhe uses ed25519-dalek
2.2.0 `verify_strict`. The positive message is UTF-8 `arkhe-interop-witness-v1`
followed by one LF byte and the raw 32-byte root above, without a trailing LF.

For quorum, `trusted` is an out-of-band test trust configuration mapping unique
witness IDs to public keys and nonempty operator labels. Require threshold > 0.
Resolve every submitted witness by ID, verify every signature on the same message,
and reject the whole case for an unknown ID, invalid signature, repeated key or
repeated operator. Accept only if the remaining distinct operator count reaches
the threshold. These checks are the proposed policy in the existing
`gravit_interop` example, not an existing production quorum API. Operator labels
are assumed configuration, not proof of real-world independence.

For byte reproduction only, the original fixture generator used Ed25519 private
seeds consisting of 32 repetitions of byte 01, 02 and 03 for w0, w1 and w2;
operators are op0, op1 and op2. These are public test keys. The positive quorum
contains signatures from w0 and w1. The dependent case changes w1's operator to
op0; the alias case assigns w0's key and signature to w1 as well. The original
generator is `../gravit-2026-10-26/prepare.py` (Python cryptography 50.0.1).
Independent comparison must consume the frozen bytes rather than regenerate them.

## Reproduce and independently cross-check

From the workspace root, with Python 3 and Rust/Cargo installed:

```powershell
python verification/interop/gravit-golden-v1/verify.py
```

This verifies SHA-256 pins, runs the existing Rust example with `cargo run --locked`,
and compares all eight ordered `{id, accepted}` outputs with static expectations.
Cargo may download locked dependencies on a clean machine; fixture verification
does not fetch Gravit data or execute Gravit code.

An independent verifier should first check `manifest.json` hashes, implement the
three checks above, consume `arkhe-vectors.json`, emit one `{id, accepted}` per
input in order, and compare with `expected.json` (ignore its explanatory reason).
Report implementation/version and all eight verdicts. Use the wider exchange
for additional edge cases. This set does not establish universal agreement on
adversarial Ed25519 encodings, full Gravit decisions, hosted inclusion, registry
thresholds or timestamp validation.

The manifest pins this specification, fixtures, verifier script, existing Rust
runner, inclusion implementation, crate manifests and lockfile. It is a local
byte snapshot, not a signed attestation or an Arkhe Git revision. Preserve the
manifest digest separately when exchanging the set; an untrusted manifest alone
does not authenticate itself. The older frozen exchange is unchanged.
