SEÇÃO 3 // PROTOCOLOS E TIPOS SPECIFICATION AKG-CBOR-v1

Contratos Canônicos, Tipos Fundamentais & Domain Separation

Codificação canônica determinística sem ambiguidades de serialização. Prefixos rígidos de Domain Separation (0x00 para folhas de Merkle, 0x01 para nós internos).

DOMAIN SEPARATION SPEC RFC 8949 + ARKHE-EXT-01

Para mitigar ataques de colisão de extensão de Merkle de comprimento variável, toda derivação BLAKE3 injeta um byte de domínio canônico obrigatório:

0x00 : LEAF_PREFIX
H_leaf = BLAKE3(0x00 || CBOR(LeafData))
0x01 : INTERNAL_NODE_PREFIX
H_parent = BLAKE3(0x01 || LeftChild || RightChild)

// ARKHE KERNEL CANONICAL TYPES - AKG-CBOR-v1 SPECIFICATION
#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Serialize, Deserialize)]
pub struct ContentHash(pub [u8; 32]); // 256-bit BLAKE3 digest

#[derive(Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct DID(pub String); // "did:arkhe:tenant-fiduciary-v1:..."

#[derive(Clone, Serialize, Deserialize)]
pub struct WorkIntent {
    pub operation_id: ContentHash,
    pub proposer_did: DID,
    pub payload_digest: ContentHash,
    pub max_gas_limit: u64,
    pub created_epoch_ns: u64,
}

#[derive(Clone, Serialize, Deserialize)]
pub enum AuthorizationDecision {
    Allow { capability_token: ContentHash, valid_until_epoch: u64 },
    Reject { reason_code: u16, violation_invariant: &'static str },
}

#[derive(Clone, Serialize, Deserialize)]
pub struct WorkerExecutionRecord {
    pub intent_ref: ContentHash,
    pub state_root_after: ContentHash,
    pub cycles_consumed: u64,
    pub fiduciary_signature: [u8; 64],
}

/// MMR Profile com Domain Separation (0x00 para Folhas, 0x01 para Pais)
pub trait MMRProfile {
    fn hash_leaf(leaf: &WorkerExecutionRecord) -> ContentHash;
    fn hash_parent(left: &ContentHash, right: &ContentHash) -> ContentHash;
    fn bag_peaks(peaks: &[ContentHash]) -> ContentHash;
}
