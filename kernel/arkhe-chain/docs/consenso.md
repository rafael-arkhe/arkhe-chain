# Tip, fork, and finality

A block is adopted only when the parent is the current tip and height is tip plus one. The proposer signs with Ed25519, domain `AKG:CHAIN:PROPOSER:v1`, over the header without signature and over transactions. The signature is 64 bytes. The key must be that of `node_id` in the validator set. `block_seal` and `BlockSeal` are not part of the API. The encoded block does not carry the `ARKH` marker.

## Fork and equivocation

A block with the same parent and height from another proposer that reproduces parent state is `Fork`. Tip and canonical balances stay. Repeating the same sibling does not increase the count. A parent that is not the canonical parent at that height is `ParentMismatch` and is not recorded.

Two distinct blocks from the same proposer at the same height are `Equivocation`. State and tip stay. The same block imported again is `ParentMismatch`.

Sync that finds a sibling records `Fork` and returns `P2p("fork")`. Sync that finds equivocation returns `Equivocation` and does not store the block. A longer chain does not replace the local tip.

There is no reorg. The precommit threshold does not change the tip.

## Finality

`finality(height)` returns `Finality { height, depth }`, with `depth = tip − height`. Missing height, including 0, is `UnknownBlock`. This describes the local canonical chain. It is not a justified checkpoint.

`Precommit` is a local Ed25519 signature on domain `AKG:CHAIN:PRECOMMIT:v4`, over height, round, block hash, a single-part header, and identifier `arkhe-chain`. That part must be 1 and the part hash must be the block hash. Another identifier is `ChainId`. The block is not split. It is not a CometBFT `CanonicalVote` or `CanonicalPartSetHeader`. Each configured validator has weight 1 and one vote per height. Uma rodada maior, no mesmo hash, substitui a anterior. A lower round is `RoundRegression`. A vote refused for lower round does not hide the next validator and does not change the tip. Alone, the result remains `RoundRegression`. The operator pass ends. A refused proposer signature does not hide the next validator and does not change the tip. Alone, the result remains `BadProposerSignature`. The operator pass ends. A signer who is not the proposer does not hide the next validator and does not change the tip. Alone, the result remains `NotProposer`. The operator pass ends. A vote refusal for another reason does not hide the next validator and does not change the tip. Alone, the result remains `P2p("vote")`. The operator pass ends. Equivocation still ends the pass immediately. A height that does not confirm does not hide the next block. That block’s vote is sent. The tip does not change. Confirming that later height remains `CommitGap`. A body that leaves no 4096 bytes for the envelope inside the 1 MiB request is left out. The vote continues without that body. The tip does not change. A synced body whose proposer signature does not verify does not hide the next peer and does not enter the chain. Alone, the result remains `BadProposerSignature`. The operator pass ends before seal. A proposer that is not a validator does not hide the next peer and does not enter the chain. Alone, the result remains `NotProposer`. The operator pass ends before seal. Equivocation still ends the list immediately. Another part total, or another part hash, is `BadPartSet` and does not enter. A vote refused for different part does not hide the next validator and does not change the tip. Alone, the result remains `BadPartSet`. The operator pass ends. `bft_commit` counts only the highest round and succeeds only when it passes two thirds. Success stores the next unconfirmed height. A height above that is `CommitGap`. Tip hash does not change. A quorum that later fails does not erase the stored height. Without file, height stays in memory. With file, `AKGCHNS9` stores that height; `AKGCHN10` stores height and sync cursor. Protocol `/arkhe/precommit/1` carries that precommit to a named validator. Receiver stores the vote and tries the next height. If the vote enters, the response returns the receiver’s own v4 precommit when it already has one. Sender stores its own vote before dialing; when it verifies, stores returned vote and tries the same height. Refused vote does not bring that return. If vote enters and receiver has not signed that canonical height, it signs round 0 before responding. An old signature, versions 1 through 3, is not returned. Bad signature, unknown hash, and outsider peer return as error and do not enter. A prior round does not count. With two validators, both at round 0 pass; if only one raises round, result returns to `QuorumAbsent`. `AKGCHNS5` and `AKGCHNS6` reopen old precommit without round in signature as round 0. A vote marked version 2 in `AKGCHNS7` reopens signature binding only round. Version 3 reopens part signature without identifier. `note_precommit` does not accept those old signatures. The tip does not move.
