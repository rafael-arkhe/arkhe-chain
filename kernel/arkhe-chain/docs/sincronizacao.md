# Synchronization

Protocol is `/arkhe/block-sync/1`, libp2p 0.54.1 CBOR request-response. Server listens with validator Ed25519 key. `spawn_server` uses `127.0.0.1` and an ephemeral port. `spawn_server_on` listens on the given address, which must not include a peer id. The `arkhe-chain` process opens a file from a key genesis, listens on that address, dials named peers, and signs round 0 of the next height that already exists. The `listen` line carries that validator’s `/p2p/` and serves as value for `--peer`. `--announce` writes that same address on one line and the next `# genesis` with BLAKE3. `--peer-file` keeps dialing only those addresses. If that line exists and local text has another BLAKE3, process exits with `Genesis` and does not create the file. If the file was created this startup and dial fails before storing block, transaction, or sibling, that file is deleted. A file that already existed stays in place. Two different hashes in the list are `Malformed`. `--peer-file` reads those lines, ignores empty and `#` comments, and dials only those peers. A failed write ends the process. This does not discover peers. `--show-peers` with `--genesis` prints id and peer id of each file validator without opening chain. `--show-genesis` prints count and BLAKE3 of that file’s canonical form. Comment and empty line do not change hash. Does not open chain. `--status` with `--data` prints height, confirmed height, tip, how many transactions wait, how many siblings are stored, and BLAKE3 stored in the file, and does not rewrite the file. Without those 32 bytes the line is `genesis absent`. With `--genesis`, text must have the same BLAKE3; other text, or file without hash, is `Genesis` and the file is not rewritten. Starting process on existing file without same hash is also `Genesis`, without rewrite. New file is still created. While process runs, it holds `<data>.lock`. Another process on same file is `Busy` and does not rewrite it. `--status` does not take that lock. Leftover `.lock` after process ends does not block next startup. A sibling does not change the tip. Chain error prints and process exits code 1. Incorrect use exits code 2 without that line. `--tx` reads canonical transactions with `u32` size. Without `--seal`, with named peers, those transactions go via `/arkhe/tx/1` before sync. `--seal` with `--time` seals a block at that instant when height is still 0. After syncing, next block uses parent timestamp plus one. That block’s vote is stored. If the peer still lacks it, response is `unknown` and the process continues. Without local transactions and without `--once`, process seals each accepted transaction from a named peer. First block uses `--time`. Next uses parent timestamp plus one. When quorum closes a height, receiver signs round 0 of next height if that block already exists. Both flags go together. Two processes with `--seal` may fork. The process does not choose proposer. With `--once`, exits after that. Then prints height, confirmed height, tip, mempool, and how many siblings are stored. Without `--once`, listen stays up and every second process dials named peers again and signs round 0 of next existing height. Prints again only when one of those values changes. A sibling does not change the tip. It is not a new round. Error in that pass ends process. It is not a new round. Does not open another round. Same node keeps same peer id. `accepted_peers` returns only that set, in id order. `sync_configured` dials that list in given order. Empty list is `P2p("empty")`. Own id is skipped. Any other error, including 128-header limit, aborts list. Before import, client checks genesis BLAKE3. Different or missing hash is `P2p("genesis")` and no block enters, even when both tips match. Transaction or precommit with different BLAKE3 is also refused, without mempool and without storing vote. No Kademlia, mDNS, or bootstrap. Out-of-set peer is `P2p("peer")` before any import. Same key is `P2p("self")` and does not dial itself. Validator that completes connection but does not speak this protocol returns `P2p("unsupported-protocol")` without waiting 30 seconds. An announced tip without 32 bytes is `P2p("tip")`. A body whose hash is not the request is `P2p("hash")`. Neither imports block. `/arkhe/precommit/1` sends already-signed precommit to named validator. Receiver stores the vote and tries the next height. Response returns receiver v4 precommit when vote enters. Sender stores that vote. A refused vote brings no return. This does not discover peers and is not a `CanonicalVote`.

Requests are `Tip`, `Block { hash }`, and `Child { parent }`. `fetch_tip_block` does not exist. Importing only tip block of a height-2 chain is `ParentMismatch`. Adhesion is `sync_canonical`, which links each ancestor.

One call walks at most 128 headers toward local tip and keeps already-checked body. Cursor remains for whole range. Call that finds local tip imports those bodies oldest to newest without asking again. Different announced tip discards cursor and retained bodies. They do not enter new chain. When node has file, limit writes `AKGCHNS8` with announced tip, cursor, and checked bodies. Reopen continues this walk. Listening process also does not exit at that limit: next pass continues cursor. That limit does not hide the next named peer. If nobody imports, the result remains `P2p("sync-limit")`. A validator that does not speak the protocol does not hide the next peer. Alone, the result remains `P2p("unsupported-protocol")` and nothing is imported. A body whose hash does not match does not hide the next peer. Alone, the result remains `P2p("hash")` and nothing is stored. An announced tip without 32 bytes does not hide the next peer. Alone, the result remains `P2p("tip")` and nothing is stored. A peer that is not a validator does not hide the next peer. Alone, the result remains `P2p("peer")` and nothing is stored. A refused dial does not hide the next peer and does not wait 30 seconds. Alone, the result remains `P2p("dial-failure")` and nothing is stored. The 30-second limit remains when dial produces no error. A connection that drops during the request does not hide the next peer. Alone, the result remains `P2p("connection-closed")` and nothing is stored. A body that does not decode does not hide the next peer. Alone, the result remains `Malformed` and nothing is stored. A request with no response in 10 seconds does not hide the next peer. Alone, the result remains `P2p("rr-timeout")` and nothing is stored. A response the codec cannot read does not hide the next peer. Alone, the result remains `P2p("io")` and nothing is stored. A refused dial does not crash the process: next pass retries and nothing from that failure is stored. Equivocation and different genesis still end the pass. Different genesis ends even when another named peer answered, and no block is sealed. A body whose hash does not match ends the pass the same way: the other peer’s block may stay imported, and the local transaction is not sealed. A body that does not decode ends the pass the same way. An announced tip without 32 bytes ends the pass the same way. A missing body, that returns `P2p("fork")` and does not store sibling, ends the pass the same way. A stored sibling stays 0 and is not this failure. A peer that is not a validator ends the pass the same way, before dial. A vote refused for different genesis ends the pass even when another validator accepts a vote. Block sealed before that vote remains. Public attest call still returns confirmed height. A vote refused for different chain identifier ends the pass the same way and does not change the tip. A vote refused for different part ends the pass the same way and does not change the tip. A vote refused for lower round ends the pass the same way and does not change the tip. A vote refused for proposer signature ends the pass the same way and does not change the tip. A vote refused because signer is not proposer ends the pass the same way and does not change the tip. A vote refused for another reason ends the pass the same way and does not change the tip. A height that does not confirm does not hide the next block: vote is sent, tip does not change, and confirming that later height remains `CommitGap`. A body that leaves no 4096 bytes for the envelope inside the 1 MiB request is left out. The vote continues without that body. A synced body whose proposer signature does not verify ends the pass even when another peer imported a block. Nothing is sealed. Alone, the result remains `BadProposerSignature`. A synced body whose proposer is not a validator ends the pass the same way and does not enter the chain. Alone, the result remains `NotProposer`. With named peers, seal waits for this pass to hear all of them. A peer not reached does not let another seal. Until then the transaction stays in mempool and no block is produced. A peer that answered with sibling does not count as absent. A peer whose announced tip is already on this chain but is not local tip does not let this pass seal the next block. Announcing local tip without delivering body also does not release seal. A body that is not that block also does not release, and the pass continues. Height-zero tip has no body. An empty list still seals before the response. Transaction response does not dial. With named peers it only enters mempool; next pass seals after hearing one of them. Finishing import clears cursor and file returns to `AKGCHNS7`. Node without file keeps cursor only in memory. `AKGCHNS7` opens without cursor. Announced tip that is already local canonical block returns 0. Local tip does not change and no sibling is stored. That 0 does not end the list: next named peer is still dialed. A peer that imports blocks does not end the list. The result is the sum of imported blocks. If all return 0, result is 0. A missing body, `P2p("fork")`, does not hide the next peer. If nobody imports, the result remains `P2p("fork")`. Equivocation and other errors still abort the list. Different genesis does not hide the next peer. Alone, the result remains `P2p("genesis")` and nothing is imported. A peer that does not answer in 30 seconds does not hide the next. If nobody answers, the result remains `P2p("timeout")`. Local vote remains. A tip that is sibling of a canonical block stays `Fork`, returns 0, and does not change the tip. That 0 does not hide the next named peer. Next block still extends canonical tip. Missing body remains `P2p("fork")` and aborts the list. Vote carries block when body extends receiver tip by one height, body hash matches vote, and body fits in 1 MiB. Vote enters. If that height is the next unconfirmed, receiver signs round 0 and returns that vote. Two votes store height. Tip hash does not change. Vote alone does not confirm height. Learned votes are resent to named peers. With three validators, the third stores the vote it did not hear directly. Two votes among three do not confirm height. A sibling in that body stays `Fork`, does not change the tip, and the `fork` response does not end the process. A body that skips a height remains `unknown` and stores nothing. Without that body, `unknown` vote stays at sender and enters when peer imports block on its dial. Genesis parent when local tip is not genesis, or missing body, may be `P2p("fork")`. Per-call timeout is 30 seconds.

A 65-block chain finishes in one call. One of 129 finishes in two. One of 1025 finishes on the ninth call: eight return the limit and the ninth imports the 1025 retained bodies.
